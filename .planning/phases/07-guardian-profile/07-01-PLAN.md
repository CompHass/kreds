## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → next-auth signout endpoint | Ação de logout dispara POST autenticado para o endpoint de signout do next-auth; destino de redirect atravessa esta fronteira |
| SSR session → client props | `guardianName` / `guardianEmail` vêm da sessão server-side (Plano 02) e são renderizados no client |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-01 | Tampering | `signOut({ redirectTo: '/login' })` | mitigate | `redirectTo` é validado pelo next-auth contra `baseUrl`/`trustHost` do servidor; valor literal `/login` (path relativo) impede open redirect |
| T-07-02 | Information Disclosure | render de `guardianEmail` no drawer | accept | Email é o do próprio usuário logado (auto-visualização); nenhum dado de terceiros ou de outra família é exposto |
| T-07-03 | Elevation of Privilege | drawer read-only | accept | Sem Server Action de escrita (D-04); nenhum campo editável; superfície de ataque de mutação inexistente |
</threat_model>
