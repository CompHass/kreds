<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| SSR session → client props | `session.user.name` / `session.user.email` cruzam de Server Component para o Client `ParentPanelView` como props |
| client → next-auth signout | Botão "Sair" no drawer dispara logout autenticado; redirect atravessa a fronteira |
| URL param familyId → session | `page.tsx` já faz `auth()` + `redirect('/login')` sem sessão; profile é read-only da própria sessão |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-04 | Information Disclosure | `guardianEmail` prop | mitigate | Email passado server-side via props (não em URL, querystring ou localStorage); é o email do próprio usuário logado, sem cross-family leak |
| T-07-05 | Tampering | logout redirect `/login` | mitigate | `redirectTo: '/login'` (path relativo) validado pelo next-auth contra `trustHost`/`baseUrl`; sem open redirect |
| T-07-06 | Spoofing | acionadores do drawer | accept | Ambos os acionadores apenas alternam estado client-side `profileOpen`; nenhuma ação privilegiada; `page.tsx` já bloqueia acesso sem sessão via `auth()` |
| T-07-07 | Information Disclosure | drawer no DOM quando fechado | accept | Drawer permanece no DOM com `translateX(100%)` e `pointerEvents:none` no backdrop; conteúdo é apenas o próprio nome/email do usuário, sem segredos |
</threat_model>
