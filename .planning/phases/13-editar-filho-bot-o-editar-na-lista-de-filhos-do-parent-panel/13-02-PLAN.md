<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| URL param childId (client-controlled) → edit/page.tsx | A guardian can type any UUID into the /family/children/[childId]/edit URL, including a child belonging to a different family or a deactivated child |
| edit/page.tsx → EditChildForm (SSR → client hydration) | Initial values (name/age/avatar/color) are passed as props and rendered client-side; only reachable after the server-side family+active guard already passed, so no cross-tenant data can leak into the client bundle |
| EditChildForm (client) → updateChildAction (server) | Same trust boundary already covered by 13-01's threat model (T-13-01..T-13-04) — this plan only adds the client form, not new server-side trust logic |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-13-05 | Information Disclosure | edit/page.tsx — cross-family childId in URL | mitigate | The child lookup query filters on `and(eq(childProfiles.id, childId), eq(childProfiles.familyId, membership.familyId))` — a childId from another family returns zero rows, triggering the `!child` redirect before any name/age/avatar/color is read into the render tree, so no cross-tenant data is ever assembled server-side |
| T-13-06 | Information Disclosure | edit/page.tsx — inactive child in URL | mitigate | `!child.active` is checked in the same guard as T-13-05 and redirects before rendering — an inactive child's current data is never shown even though the row technically still exists in this family |
| T-13-07 | Spoofing | edit/page.tsx — unauthenticated access | mitigate | Reuses the exact `requireAuthenticatedIdentity`/`resolveKredsIdentityId` guard pattern already proven in page.tsx and actions.ts — unauthenticated requests redirect to /api/auth/signin before the child lookup runs |
| T-13-SC | Tampering | npm/pip/cargo installs | accept | No new package installed in this plan — only existing Next.js/React/Drizzle APIs already used elsewhere in the codebase |
</threat_model>
