<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Guardian browser to audit timeline | Read access to sensitive family history must be guardian-only and family-scoped. |
| Audit writer to audit reader | Metadata written by commands must be sanitized before parent display. |
| Phase 2 routes to family data | Multiple slices share family_id authorization and can regress into enumeration. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|---|---|---|---|
| T-02-16 | Information Disclosure | `listFamilyAuditTimeline` | mitigate | Require active guardian and filter by family_id before selecting audit rows. |
| T-02-17 | Information Disclosure | `sanitizeAuditMetadata` | mitigate | Strip raw invitation tokens, token hashes, raw diffs, and unnecessary sensitive fields from timeline output. |
| T-02-18 | Repudiation | family audit coverage | mitigate | Verify family creation, membership, invitation, role, consent, and child profile changes all emit audit events. |
| T-02-19 | Elevation of Privilege | family navigation and pages | mitigate | Server-side guardian checks on audit page; no client-only authorization. |
| T-02-20 | Information Disclosure | cross-family Phase 2 routes | mitigate | Integration tests assert another family cannot read child, invitation, family, or audit data. |
</threat_model>
