    Criar src/app/api/families/[familyId]/child-auth/route.ts como Route Handler Next.js App Router (não Pages Router).

    Função: `export async function POST(req: NextRequest, { params }: { params: Promise<{ familyId: string }> })`

    Fluxo completo:

    1. Extrair familyId de `await params`.
    2. Parsear body JSON: `{ childProfileId: string, pin: string }`. Retornar 400 se campos ausentes ou pin vazio.
    3. Chamar `checkBruteForce(childProfileId)`. Se blocked, retornar 429 JSON: `{ error: 'Muitas tentativas. Tente novamente em 15 minutos.' }`.
    4. Buscar no banco: `SELECT id, family_id, display_name, active, pin_hash FROM child_profiles WHERE id = $childProfileId AND family_id = $familyId LIMIT 1`. Usar `eq(childProfiles.id, childProfileId)` e `eq(childProfiles.familyId, familyId)` como filtros. Se não encontrado, retornar 404: `{ error: 'Perfil não encontrado.' }`.
    5. Se `!profile.active`, retornar 403: `{ error: 'Perfil inativo.' }`.
    6. Se `!profile.pinHash`, retornar 403: `{ error: 'PIN não configurado para este perfil.' }`.
    7. Chamar `verifyPin(pin, profile.pinHash)`. Se false:
       - Chamar `recordFailedAttempt(childProfileId)`
       - Escrever audit event: eventType='child_login_failed', subjectType='child_profile', subjectId=childProfileId, actorIdentityId=null, summary=`Tentativa de login falhou para "${profile.displayName}"`, metadata: `{ familyId }` (sem o PIN ou hash)
       - Retornar 401: `{ error: 'PIN incorreto.' }`
    8. Login bem-sucedido:
       - Chamar `resetAttempts(childProfileId)`
       - Chamar `signChildSession({ childProfileId, familyId, role: 'child' })` para obter JWT string
       - Atualizar `last_accessed_at`: `UPDATE child_profiles SET last_accessed_at = now() WHERE id = $childProfileId`
       - Escrever audit event: eventType='child_login_success', subjectType='child_profile', subjectId=childProfileId, actorIdentityId=null, summary=`Login bem-sucedido para "${profile.displayName}"`, metadata: `{ familyId }`
       - Criar NextResponse com status 200 e body `{ ok: true, childProfileId, familyId }`
       - Setar cookie no response: `response.cookies.set('child-session', jwt, { httpOnly: true, secure: true, sameSite: 'strict', path: '/', maxAge: 8 * 60 * 60 })` (8h = expire igual ao JWT)
       - Retornar response

    IMPORTANTE — Segurança de cookie (D-30):
    - httpOnly: true (obrigatório — impede leitura por JS)
    - secure: true (obrigatório — HTTPS only)
    - sameSite: 'strict' (obrigatório — CSRF protection)
    - path: '/' (escopo global)

    IMPORTANTE — Nunca logar pin raw, nunca incluir pinHash em nenhuma resposta.
  </action>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Child browser → /family/access/[familyId] | Página pública — mostra apenas displayName e avatar; nenhum dado sensível |
| Child browser → POST /api/families/[familyId]/child-auth | PIN raw em trânsito; bcrypt verify server-side; JWT emitido apenas no sucesso |
| child-session JWT cookie → child routes | Cookie httpOnly+Secure+SameSite=Strict — JS não pode ler; enviado apenas em HTTPS |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-11-01 | Spoofing | POST /api/families/[familyId]/child-auth | mitigate | bcrypt.compare com cost factor 12; resultado boolean não revela hash |
| T-02-11-02 | Denial of Service | brute-force child PIN | mitigate | 5 tentativas por childProfileId por 15 min; 429 retornado antes de qualquer DB query adicional |
| T-02-11-03 | Information Disclosure | /family/access/[familyId] | mitigate | SELECT exclui pin_hash; página mostra apenas displayName e avatar visual |
| T-02-11-04 | Tampering | child-session JWT | mitigate | Assinado com CHILD_SESSION_SECRET via HS256; verificado em cada request de rota child |
| T-02-11-05 | Elevation of Privilege | child-session cookie scope | mitigate | Cookie path='/'; sameSite=strict; não acessível por JS; expira em 8h |
| T-02-11-06 | Information Disclosure | auth endpoint response | mitigate | 401 retorna mensagem genérica 'PIN incorreto' — não revela se o perfil existe ou não existir o hash |
</threat_model>
