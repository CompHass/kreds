<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Guardian browser to invitation creation | Guardian-supplied email and action enters lifecycle command. |
| Invitation link to accept page | Bearer token crosses from URL into server command and must be hashed/validated. |
| Authenticated invitee to family membership | External identity is linked to Kreds role only after token and email checks. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|---|---|---|---|
| T-02-11 | Spoofing | `acceptGuardianInvitation` | mitigate | Require authenticated ZITADEL session and validate pending token hash before membership creation. |
| T-02-12 | Tampering | invitation status transitions | mitigate | Enforce allowed lifecycle transitions and reject terminal-state acceptance. |
| T-02-13 | Information Disclosure | invitation tokens | mitigate | Persist token hashes only and avoid logging raw tokens. |
| T-02-14 | Elevation of Privilege | invitation creation/revoke | mitigate | Require active guardian authorization for invite/revoke; invitee receives guardian role only on acceptance. |
| T-02-15 | Repudiation | invitation lifecycle | mitigate | Write sanitized audit event for pending, accepted, expired, revoked, and declined states. |
</threat_model>
