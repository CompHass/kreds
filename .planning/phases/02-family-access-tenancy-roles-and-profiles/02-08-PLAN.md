    Criar docs/ZITADEL-SETUP.md com as seguintes seções em português:

    ## Configuração do ZITADEL para desenvolvimento local

    ### Pré-requisitos
    - Acesso ao console ZITADEL em https://auth.hasslab.pro (ou solicitar ao administrador)
    - Node.js e pnpm instalados

    ### Passo 1: Criar ou localizar o Application no ZITADEL
    Descrever: Console ZITADEL → Organization → Projects → kreds (ou criar) → Applications → Add → Type: Web → Authentication Method: PKCE ou Code (recomendado Code + secret)

    ### Passo 2: Configurar Redirect URIs
    URIs obrigatórios para dev local:
    - http://localhost:3000/api/auth/callback/zitadel (callback de login)
    - http://localhost:3000 (post-logout redirect)
    Ativar "Dev Mode" no ZITADEL application para permitir HTTP (não HTTPS) em localhost

    ### Passo 3: Obter Client ID e Client Secret
    Onde encontrar: Applications → [nome do app] → Client ID (visível), Client Secret (gerar em Keys)

    ### Passo 4: Gerar AUTH_SECRET
    Comando: `openssl rand -base64 33`
    Copiar o output e usar como AUTH_SECRET

    ### Passo 5: Criar .env.local
    Mostrar template completo:
    ```
    DATABASE_URL=postgresql://kreds:kreds_dev@localhost:5432/kreds_dev
    NODE_ENV=development
    NEXT_PUBLIC_APP_URL=http://localhost:3000
    AUTH_SECRET=<output do openssl>
    AUTH_ZITADEL_ID=<client-id do ZITADEL>
    AUTH_ZITADEL_SECRET=<client-secret do ZITADEL>
    AUTH_ZITADEL_ISSUER=https://auth.hasslab.pro
    ```

    ### Passo 6: Verificar configuração
    `bash scripts/check-auth-config.sh`

    ### Passo 7: Testar login
    `pnpm dev` → abrir http://localhost:3000 → clicar "Entrar com ZITADEL" → deve redirecionar para auth.hasslab.pro → após login retornar para http://localhost:3000

    ### Solução de problemas comuns
    - "redirect_uri_mismatch": o URI cadastrado no ZITADEL não bate com /api/auth/callback/zitadel
    - "CLIENT_FETCH_ERROR": AUTH_ZITADEL_ISSUER inacessível ou AUTH_SECRET inválido
    - Página em branco após login: AUTH_SECRET gerado diferente entre sessões (use .env.local, não variável de shell)
    - "Authentication required — no ZITADEL subject (sub) in session": callback JWT não preservou profile.sub — verificar se scope inclui "openid"

    ### Scopes necessários
    O app ZITADEL deve ter: openid, email, profile, offline_access (conforme configurado em auth.ts)

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → Next.js Auth.js route | OIDC authorization code flow — callback receives code from ZITADEL |
| ZITADEL → Next.js | Token exchange — client secret must not be logged or exposed |
| .env.local → process | Secrets must not be committed or echoed in script output |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-GC01 | Information Disclosure | scripts/check-auth-config.sh | mitigate | Script must not print secret values — print only presence/absence. Use `[SET]` vs `[MISSING]` labels, never the actual value |
| T-02-GC02 | Spoofing | AUTH_ZITADEL_ISSUER | mitigate | Script validates issuer is reachable and returns valid OIDC discovery document (checks for "issuer" key in JSON) |
| T-02-SC | Tampering | npm/pip/cargo installs | accept | No new packages installed in this plan — script uses only bash builtins and curl |
</threat_model>
