    Imports:
    - `import { NextRequest, NextResponse } from 'next/server'`
    - `import { cookies } from 'next/headers'`
    - `import { z } from 'zod'`
    - `import { db } from '@/lib/db'`
    - `import { ledgerTransactions, ledgerLines } from '@/lib/db/schema'`
    - `import { calculateFirstfruits } from '@/modules/ledger/calculate'`
    - `import { verifyChildSession } from '@/lib/families/child-session'`
    - `import { validateChildSessionScope } from '@/lib/auth/child-guard'`

    Define the Zod schema:
    ```
    const HarvestBodySchema = z.object({
      commandId: z.string().uuid('commandId must be a UUID'),
      totalAmount: z.number().int().positive('totalAmount must be a positive integer'),
      familyId: z.string().uuid('familyId must be a UUID'),
    })
    ```

    Export the POST handler:
    ```
    export async function POST(
      req: NextRequest,
      { params }: { params: Promise<{ childId: string }> }
    )
    ```

    Implementation steps:

    1. `const { childId } = await params` — CRITICAL: await params in Next.js 15+.

    2. Auth — read child session cookie:
       ```
       const cookieStore = await cookies()
       const token = cookieStore.get('child-session')?.value
       if (!token) return NextResponse.json({ error: 'Unauthorized' }, { status: 401 })
       ```

    3. Verify JWT:
       ```
       let session: { childProfileId: string; familyId: string; role: 'child' }
       try {
         session = await verifyChildSession(token)
       } catch {
         return NextResponse.json({ error: 'Unauthorized' }, { status: 401 })
       }
       ```

    4. Scope check:
       ```
       if (!validateChildSessionScope(session, childId)) {
         return NextResponse.json({ error: 'Forbidden' }, { status: 401 })
       }
       ```

    5. Parse body:
       ```
       let rawBody: unknown
       try {
         rawBody = await req.json()
       } catch {
         return NextResponse.json({ error: 'Invalid body' }, { status: 400 })
       }
       ```

    6. Validate with Zod:
       ```
       const result = HarvestBodySchema.safeParse(rawBody)
       if (!result.success) {
         return NextResponse.json({ error: result.error.flatten() }, { status: 400 })
       }
       const { commandId, totalAmount, familyId } = result.data
       ```

    7. Calculate split:
       ```
       const firstfruits = calculateFirstfruits(totalAmount)
       const available = totalAmount - firstfruits
       ```

    8. Atomic write in db.transaction():
       ```
       try {
         const txn = await db.transaction(async (tx) => {
           const [header] = await tx
             .insert(ledgerTransactions)
             .values({
               commandId,
               familyId,
               childProfileId: childId,
               transactionType: 'task_earning',
             })
             .returning()

           await tx.insert(ledgerLines).values([
             { transactionId: header.id, childProfileId: childId, accountType: 'available', amount: available },
             { transactionId: header.id, childProfileId: childId, accountType: 'firstfruits', amount: firstfruits },
           ])

           return header
         })

         return NextResponse.json(txn, { status: 201 })
       } catch (err: unknown) {
         if (err && typeof err === 'object' && 'code' in err && (err as { code: string }).code === '23505') {
           return NextResponse.json({ error: 'Already harvested' }, { status: 409 })
         }
         throw err
       }
       ```

    CRITICAL constraints:
    - NEVER use `onConflictDoNothing()` — it silently skips and makes 409 impossible to detect.
    - NEVER catch 23505 inside the transaction callback — catch it outside the `db.transaction()` call.
    - NEVER skip the `validateChildSessionScope` check — this is the ownership guard preventing child A from harvesting child B's ledger.
    - The `familyId` in the request body is ALSO validated against the session? For v1, the familyId from the body is used (session.familyId could also be used). Use session.familyId for the insert rather than body.familyId to prevent forgery — update the insert to use `familyId: session.familyId` instead of `familyId` from body.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| child browser → harvest route | commandId, totalAmount from untrusted client — validated before DB write |
| child session cookie → route handler | JWT must be verified; scope must match URL childId |
| familyId in request | Use session.familyId not body.familyId to prevent cross-family ledger writes |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-09 | Spoofing | POST /api/child/[childId]/harvest | mitigate | verifyChildSession() validates JWT signature; missing or expired token returns 401 |
| T-06-10 | Elevation of Privilege | harvest route childId param | mitigate | validateChildSessionScope() checks session.childProfileId === URL childId; child A cannot harvest for child B |
| T-06-11 | Tampering | harvest replay attack | mitigate | Unique index on commandId + catch 23505 → 409; client retries same commandId safely |
| T-06-12 | Tampering | float totalAmount from client | mitigate | Zod z.number().int().positive() rejects non-integer amounts before calculateFirstfruits is called |
| T-06-13 | Tampering | familyId forgery in request body | mitigate | Use session.familyId for the ledger insert, not body.familyId — session is signed JWT, cannot be forged |
| T-06-14 | Tampering | negative or zero totalAmount | mitigate | Zod z.number().positive() rejects; calculateFirstfruits also throws for amount <= 0 |
| T-06-SC | Tampering | npm installs | accept | No new packages — all deps verified in prior phases |
</threat_model>
