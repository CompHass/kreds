    CREATE src/app/api/family/[familyId]/tasks/route.ts:

    Imports: NextRequest, NextResponse from 'next/server'; auth from root auth.ts (path: '../../../../../auth' — adjust if needed, or use '@/auth' if configured); db from '@/lib/db'; taskTemplates from '@/lib/db/schema'; eq, and from 'drizzle-orm'; CreateTaskSchema from '@/types/task'.

    Export GET handler:
    ```
    export async function GET(
      _req: NextRequest,
      { params }: { params: Promise<{ familyId: string }> }
    )
    ```
    1. `const { familyId } = await params` — CRITICAL: await in Next.js 15+.
    2. `const session = await auth()` — if !session return 401 JSON.
    3. Query: `db.select().from(taskTemplates).where(and(eq(taskTemplates.familyId, familyId), eq(taskTemplates.isActive, true)))`.
    4. Return `NextResponse.json(tasks)`.

    Export POST handler:
    ```
    export async function POST(
      req: NextRequest,
      { params }: { params: Promise<{ familyId: string }> }
    )
    ```
    1. `const { familyId } = await params`.
    2. `const session = await auth()` — if !session return 401.
    3. Parse body: `const body = await req.json()` wrapped in try/catch (return 400 on parse error).
    4. Validate: `const result = CreateTaskSchema.safeParse(body)` — if !result.success return 400 with `result.error.flatten()`.
    5. Insert: `const [created] = await db.insert(taskTemplates).values({ ...result.data, familyId }).returning()`.
    6. Return `NextResponse.json(created, { status: 201 })`.

    CREATE src/app/api/family/[familyId]/tasks/[taskId]/route.ts:

    Imports same as above plus UpdateTaskSchema from '@/types/task'.

    Export PATCH handler:
    ```
    export async function PATCH(
      req: NextRequest,
      { params }: { params: Promise<{ familyId: string; taskId: string }> }
    )
    ```
    1. `const { familyId, taskId } = await params`.
    2. auth() check — 401 if no session.
    3. Parse + validate body with UpdateTaskSchema.safeParse — 400 if invalid.
    4. Update: `const [updated] = await db.update(taskTemplates).set({ ...result.data, updatedAt: new Date() }).where(and(eq(taskTemplates.id, taskId), eq(taskTemplates.familyId, familyId))).returning()`.
    5. If !updated return 404. Else return NextResponse.json(updated).

    Export DELETE handler:
    ```
    export async function DELETE(
      _req: NextRequest,
      { params }: { params: Promise<{ familyId: string; taskId: string }> }
    )
    ```
    1. `const { familyId, taskId } = await params`.
    2. auth() check — 401 if no session.
    3. `await db.update(taskTemplates).set({ isActive: false, deactivatedAt: new Date() }).where(and(eq(taskTemplates.id, taskId), eq(taskTemplates.familyId, familyId)))`.
    4. Return `NextResponse.json({ ok: true })`.

    CRITICAL patterns to follow:
    - Always `await params` before accessing familyId/taskId — never `params.familyId` directly.
    - Always `const [row] = await db.insert(...).returning()` — destructure array (Pitfall 2).
    - familyId isolation on EVERY query: `eq(taskTemplates.familyId, familyId)` in every WHERE clause.
    - updatedAt must be set explicitly on updates since Drizzle does not auto-update it.

    Run `pnpm tsc --noEmit` after to verify no TypeScript errors.

    EXPORT four Server Actions:

    1. `createTask(data: z.infer<typeof CreateTaskSchema> & { familyId: string }): Promise<typeof taskTemplates.$inferSelect>`:
       - `const session = await auth()` — if !session throw new Error('Unauthorized').
       - Validate with CreateTaskSchema.parse({ ...data }) — throws ZodError if invalid.
       - Insert: `const [task] = await db.insert(taskTemplates).values({ title: data.title, familyId: data.familyId, assignedChildId: data.assignedChildId, kredsValue: data.kredsValue, days: data.days, category: data.category ?? null, approval: data.approval ?? false }).returning()`.
       - `revalidatePath(`/family/${data.familyId}/tasks`)` — AFTER the insert, never inside a transaction callback.
       - Return `task`.

    2. `updateTask(taskId: string, familyId: string, data: Partial<z.infer<typeof CreateTaskSchema>>): Promise<typeof taskTemplates.$inferSelect>`:
       - auth() check — throw if no session.
       - `const [task] = await db.update(taskTemplates).set({ ...data, updatedAt: new Date() }).where(and(eq(taskTemplates.id, taskId), eq(taskTemplates.familyId, familyId))).returning()`.
       - if !task throw new Error('Task not found').
       - `revalidatePath(`/family/${familyId}/tasks`)`.
       - Return `task`.

    3. `toggleTaskActive(taskId: string, familyId: string, active: boolean): Promise<void>`:
       - auth() check.
       - `await db.update(taskTemplates).set({ isActive: active, updatedAt: new Date() }).where(and(eq(taskTemplates.id, taskId), eq(taskTemplates.familyId, familyId)))`.
       - `revalidatePath(`/family/${familyId}/tasks`)`.

    4. `deactivateTask(taskId: string, familyId: string): Promise<void>`:
       - auth() check.
       - `await db.update(taskTemplates).set({ isActive: false, deactivatedAt: new Date(), updatedAt: new Date() }).where(and(eq(taskTemplates.id, taskId), eq(taskTemplates.familyId, familyId)))`.
       - `revalidatePath(`/family/${familyId}/tasks`)`.

    PITFALL to avoid (Pitfall 6): Server Actions return the real DB row (with real UUID from .returning()). The ParentPanelView will replace the optimistic local UUID with the real one from the server action response. This prevents "fake id" desync bugs.

    PITFALL to avoid (Pitfall 4): revalidatePath receives the concrete path string with the real familyId, not a pattern. Always: `revalidatePath(\`/family/${familyId}/tasks\`)`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client request → Route Handler | familyId comes from URL params — must be cross-checked against session |
| 'use client' component → Server Action | Server Actions run server-side; auth() check required before any DB write |
| task kredsValue | DB CHECK (kreds_value > 0) enforces at DB level; Zod enforces at API level |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-04 | Elevation of Privilege | GET /api/family/[familyId]/tasks | mitigate | auth() check returns 401 if no session; familyId scoped on query |
| T-06-05 | Elevation of Privilege | POST/PATCH/DELETE task routes | mitigate | auth() check on all mutating routes; familyId on every WHERE clause prevents cross-family writes |
| T-06-06 | Tampering | kredsValue in POST/PATCH body | mitigate | Zod z.number().int().positive() rejects 0, negatives, and floats; DB CHECK as defense-in-depth |
| T-06-07 | Tampering | days field in POST body | mitigate | Zod z.array(z.number().int().min(0).max(6)) rejects out-of-range day indices |
| T-06-08 | Tampering | Server Actions — CSRF | accept | Next.js Server Actions have built-in CSRF protection (Origin header check); no additional CSRF token needed |
| T-06-SC | Tampering | npm installs | accept | No new packages — all deps verified in prior phases |
