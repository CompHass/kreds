    Create docs/PRIVACY-INVENTORY.md with the following sections, sourced from RESEARCH.md Child Privacy Data Inventory section:

    1. **Overview** — State that Kreds collects data about children ages 6+ and this inventory documents all categories before any collection begins. Reference COPPA (Children's Online Privacy Protection Act) as the governing regulation.

    2. **Data Categories Table** — Create a table with columns: Data Category, Collected In (Phase + Requirement ID), Purpose, Legal Basis, Retention. Include all 8 categories from RESEARCH.md:
       - Child display name → Phase 2 (FAM-03), Profile identification, Parental consent (parent creates profile), Until family account deleted
       - Child role assignment → Phase 2 (FAM-04), Authorization and UI gating, Parental consent, Until family account deleted
       - Child avatar/visual identifier → Phase 2 (FAM-06), Profile customization, Parental consent, Until changed or account deleted
       - Task completion records → Phase 5 (ACT-04), Earnings tracking, Parental consent (parent approves), Retained for audit/history
       - Earnings and balance data → Phase 3 (LEDG-01), Financial stewardship tracking, Parental consent, Retained for audit/history
       - Wishlist goals → Phase 6 (GOAL-01), Savings goal tracking, Parental consent, Until goal completed or deleted
       - Gratitude reflections → Phase 8 (BIBL-04), Weekly spiritual reflection, Parental consent, Retained in weekly report snapshots
       - Family membership (child as profile) → Phase 2 (FAM-03), Tenancy isolation, Parental consent, Until family account deleted

    3. **COPPA Compliance Checklist** — List all 5 requirements from RESEARCH.md:
       - Verifiable parental consent before collecting any personal information from children
       - Clear privacy policy explaining data collection practices
       - Data minimization — cannot require children to disclose more information than necessary
       - Data retention limits — keep child data only as long as needed, then securely delete
       - Parental rights — parents can review, delete, and refuse further collection of child data
       For each, add a status column: [ ] Not yet implemented (Phase 1 baseline)

    4. **Parental Consent Flow Description** — Describe that in Kreds, children are profiles under parent-managed families (not independent accounts). Parents create child profiles, assign roles, and approve all child actions (task completions, giving allocations). Consent is implicit through parent account creation and explicit through parent approval of child actions.

    5. **Data Retention and Deletion Policy** — State that child data is retained until the family account is deleted, except for audit/history records (task completions, earnings, ledger transactions) which are retained indefinitely for financial integrity. On family deletion, all child data is securely deleted except anonymized aggregate statistics.

    6. **Third-Party Data Sharing Policy** — State that Kreds v1 shares NO child data with third parties. No analytics, no advertising, no external payment processors (deferred to v2+), no charity marketplace (deferred to v2+). All data stays within the Kreds application and PostgreSQL database.

    7. **What Phase 1 Does NOT Collect** — Explicitly list: No child profile data, no child authentication, no personal identifiers beyond display name, no location data, no behavioral tracking or analytics on child users.

    8. **Contact Information** — Placeholder for privacy inquiries: privacy@kreds.app (to be configured before production launch).

    9. **Review Sign-Off** — Section for maintainer review: "This inventory was reviewed on [date] by [maintainer]. All data categories are documented. No child data collection begins until this inventory is approved."

       - Task Completion: Child's submission of completed task occurrence requiring parent approval. Context: ACT-04.
       - 72-Hour Rule: Blocks task completion submissions more than 72 hours after occurrence date. Context: ACT-05.
       - Weekly Cycle: Activity period Sunday through Saturday. Context: ACT-02.
       - Weekly Gratitude Report: Immutable snapshot of weekly stewardship activity. Context: BIBL-04 through BIBL-06.
       - Wishlist Goal: Savings target with target amount and progress indicator. Context: GOAL-01.
       - Guardian: Parent/guardian role in Kreds domain model. Context: FAM-04.
       - Child: Child profile role managed by guardians. Context: FAM-04.
       - Family: Core tenancy unit, all data isolated by family_id. Context: FAM-01.
       - Kreds Engine: Financial engine processing all Kreds movements. Context: LEDG-01 through LEDG-08.
       - Negative Adjustment: Debit entry for misaligned behaviors with reason and optional restoration note. Context: LEDG-05.
