  <name>Task 1: Make root page redirect based on auth + family membership</name>
  <files>src/app/page.tsx</files>
  <action>
    Rewrite `src/app/page.tsx` as an `async` default-exported Server Component that mirrors the resolution logic in `src/app/family/page.tsx`, differing only in the final redirect target.

    Steps, in order:
    1. Import `redirect` from `next/navigation`, `auth` from the repo-root `auth` module (from `src/app/page.tsx` the relative path is `'../../auth'` — note this is one level shallower than `family/page.tsx`, which uses `'../../../auth'`), `db` from `@/lib/db`, `identities` and `familyMemberships` from `@/lib/db/schema`, and `and`, `eq` from `drizzle-orm`.
    2. `const session = await auth()`. If `!session?.user?.id`, `redirect('/login')`.
    3. Look up the identity by `eq(identities.zitadelSubject, session.user.id)`, selecting `{ id: identities.id }`, `.limit(1)`, take first row. If no identity, `redirect('/login')` (mirrors the family-page fallback for consistency, per constraints).
    4. Look up the active membership with `and(eq(familyMemberships.identityId, identity.id), eq(familyMemberships.status, 'active'))`, selecting `{ familyId: familyMemberships.familyId }`, `.limit(1)`, take first row. If no membership, `redirect('/login')`.
    5. On success, `redirect(\`/family/${membership.familyId}/tasks\`)` — NOTE: target is the tasks dashboard, NOT `/family/access/${familyId}`. The user explicitly wants the guardian's tasks dashboard as the landing page, skipping the profile-selection screen.

    Remove the existing static `<main>`/`<p>Kreds v2.0</p>` JSX entirely — the component no longer renders; every code path ends in a `redirect()`.

    Do NOT modify `src/middleware.ts`: `/` is already a public pass-through (middleware.ts line 19), and the redirect belongs in the page itself — the same architecture `/family` already uses. Do NOT touch `/family/access/[familyId]` or any child-session flow.
  </action>
